Prototype limitations

  • No back-end, authentication or real database; data lives in JavaScript objects and localStorage.
  • Availability is a recurring weekly slot (no calendar dates, time zones or recurring-booking logic).
  • Tutor ratings, rates and profiles are synthetic; no reviews, payments or notifications.
  • Weighted-sum matching is transparent but not learned from data; weights are hand-chosen defaults.
  • Conflict checks run in the browser only; a production system must enforce them server-side in a database transaction.
